# README Maintenance (keep the project README in sync)

> Generic foundation doc. Copied verbatim into every project's `project-setup/readme-maintenance.md`.
> The **project's own `README.md`** should always reflect the current foundation details (stack, chosen state library, API transport, scripts, and the `project-setup/` index). This doc defines how the agent keeps it accurate **without duplicating files or clobbering your content** — and the one rule that it **always asks before writing**.

## The rule (non-negotiable)

- **Never duplicate.** There is exactly one `README.md` at the project root. Update it in place — do not create `README.new.md`, `PROJECT_README.md`, etc.
- **Always ask first.** Before writing any README change, the agent asks: *"Update README.md for these changes? (y/n)"* and shows what it will write. No silent README edits.
- **Preserve user content.** Only a single marked block is managed; everything the user wrote outside it is left untouched.
- **Create if missing.** If the project has no `README.md`, the agent offers to create one (still asking first).

## The managed block

The auto-generated foundation section lives between two HTML-comment markers. The agent replaces only what is between them; it never edits outside them.

```md
<!-- super-react:start -->
## Tech Stack
<!-- auto-generated by super-react-foundation — edits inside this block are overwritten -->
...generated content...
<!-- super-react:end -->
```

- **Block exists** → replace its contents in place.
- **No block, README exists** → ask where to insert it (default: after the title/intro), then add the markers.
- **No README** → offer to create one with a title + the block.

## What goes in the block

A compact, factual snapshot — regenerated from current project state, never hand-maintained:

- **Tech stack** — React + TypeScript + Vite, MUI, React Query, the chosen **state library** (Redux/Zustand), and the **API transport** (typed client or generated SDK).
- **Getting started** — `install` / `dev` / `build` / `lint` / `test` (and `generate-sdk` when the SDK option is on).
- **Project structure** — one-liner pointing at `src/` and the feature-slice layout.
- **Documentation index** — a link list to the seeded `project-setup/*.md` (start at `how-it-works.md`).
- **Foundation status** — state library + API transport + a pointer to `FOUNDATION_COMPLETE.md`.

> Keep it short. Long-form architecture lives in `project-setup/`, not the README — the README links to it.

## When the agent offers to update it

The agent proposes a README update (and asks first) whenever foundation-visible details change:

| Trigger | What changes in the block |
|---|---|
| `setup-project-foundation` finishes | full block created/refreshed (stack, scripts, docs index, status) |
| state library re-wired (`scaffold --force --state=…`) | state-library line + status |
| API transport changes (default ↔ `--sdk`) | API line, `generate-sdk` script, status |
| a feature adds a script or env var | scripts / getting-started lines |
| `project-setup/` docs added or renamed | documentation index |

If nothing foundation-visible changed, the agent does **not** prompt — no noise.

## Adapt per project

- The user's own README prose (badges, screenshots, contribution notes) stays outside the block and is never touched.
- If the team prefers the foundation snapshot in a separate `docs/` page instead of the README, move the markers there — the same "ask first, single managed block" rules apply.
