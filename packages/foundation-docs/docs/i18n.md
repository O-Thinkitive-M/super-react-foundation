# i18n & Text Registry

> Generic foundation doc. Copied verbatim into every project's `project-setup/i18n.md`.
> **No literal text in any component.** Every string flows through a typed `t()` from the `src/i18n/` registry. Framework: **react-i18next** + typed keys (autocomplete + compile error on a missing key).

## Why

- Single source of truth for copy → consistent, reviewable, translatable.
- Typed keys → renaming/missing keys are **compile errors**, not runtime blanks.
- WCAG / locale / RTL ready from day one.

## What the scaffold seeds (working today)

| Path | Holds |
|---|---|
| `src/i18n/index.ts` | i18next init + `t` / `useTranslation` / `setLocale` exports |
| `src/i18n/react-i18next.d.ts` | typed `t()` — missing/typo keys are compile errors |
| `src/i18n/en/index.ts` | assembles the `common` namespace from the category files |
| `src/i18n/en/buttons.ts` | button + action text |
| `src/i18n/en/titles.ts` | page / section / dialog titles |
| `src/i18n/en/labels.ts` | field + UI labels (supports `{{interpolation}}`) |
| `src/i18n/en/descriptions.ts` | helper / empty-state / warning copy |

The default app boots with **one locale (`en`) loaded eagerly** and **one namespace (`common`)** — zero config, the demo screen has no hardcoded strings.

## Category file shape

```ts
// src/i18n/en/buttons.ts
export const buttons = {
  getStarted: "Get Started",
  cancel: "Cancel",
  save: "Save",
} as const;
```

Add more categories as the app grows (`validation.ts` for zod messages, `tableHeaders.ts` for DataTable columns, `enums.ts` for status labels, `messages/success.ts`, `messages/error.ts`) and register them in `en/index.ts`.

## How components consume text

```tsx
import { useTranslation } from "@/i18n";
const { t } = useTranslation();

<Button>{t("buttons.getStarted")}</Button>
toast.success("messages.success.saved");                 // outside React: import { t } from "@/i18n"
<DataTable columns={[{ key: "name", headerKey: "tableHeaders.name" }]} />  // *Key props, resolved internally
```

- DataTable/forms/overlays take **`*Key`** props (string keys), never resolved strings — they call `t()` internally.

## Interpolation & pluralization

```ts
// labels.ts
itemCount_one: "{{count}} item",
itemCount_other: "{{count}} items",
```
```tsx
t("labels.itemCount", { count });       // picks _one/_other by count
t("messages.success.created", { name }); // interpolation
```

## Typed keys (compile error on missing key)

`react-i18next.d.ts` binds `t()` to the `en` bundle, so `t("buttons.getStrated")` is a TS error. When you add namespaces, extend the typed resources here too.

## Add a string (workflow)

| Step | Action |
|---|---|
| 1 | Add the key to the right category file (`buttons.ts`, `validation.ts`, …). |
| 2 | Use it: `t("category.key")` — autocomplete confirms it exists. |
| 3 | (Multi-locale) add the same key to every locale; a CI check fails on drift. |

## Upgrade path — locales, namespaces, RTL

- **More locales:** mirror `en/` into `es/`, `ar/`, … and switch `index.ts` to the lazy `i18next-resources-to-backend` loader so only the active (locale, namespace) is fetched.
- **Namespaces:** keep shared copy in `common.*`; put area-specific copy in its own namespace (e.g. `admin:*`). Type every namespace so all keys are compile-checked.
- **RTL:** `setLocale("ar")` flips `document.dir`; the MUI theme reads `direction` and `stylis-plugin-rtl` mirrors layout. Use logical CSS (`marginInlineStart`) in primitives.
- **CI validation:** English is the source of truth; a script diffs each locale's key set per namespace and fails on any missing/extra key.

## Enforce no hardcoded text (lint)

Add `eslint-plugin-i18next`'s `no-literal-string` rule (see `quality-gates.md`) so CI fails on any raw JSX string or untranslated `label`/`placeholder`/`aria-label`/`alt`.

## Keep out of the bundle

Long-form legal/consent/marketing/template content is served from the backend/CMS at runtime — **not** placed in i18n category files. The registry is for **UI chrome only** (labels, buttons, titles, validation, enums, toasts).

## Adapt per project (from UI/SRS/MOM)

- Replace the demo keys with the project's real copy (keep the category structure).
- Decide the locale set and whether RTL is required, then apply the upgrade path above.
